# Techniques

Patterns that outgrow a single problem. Each note works out one mechanism in detail, so the problem solutions can use it without re-deriving it — and so the edge cases live in one place rather than being copied between solutions.

[Where the slow pointer lands](./fast-slow-pointers.md) traces the fast/slow middle loop for odd and even lists, derives the landing index, explains why `fast` starts at `head.next`, and covers the loop that lands one node earlier. [Splitting a linked list at the middle](./splitting-a-linked-list.md) is the two-line cut that turns one list into two, and the order the two lines have to be written in. [Reversing instead of stacking](./reverse-instead-of-stack.md) explains why a backwards traversal is a choice between `O(n)` memory and mutation. [Attaching the remainder after a merge](./merge-remainder.md) covers the `curr1 or curr2` line that finishes a two-list merge. [Heap tuples](./heap-tuples.md) explains the priority, tiebreaker, payload shape that keeps a heap from ever comparing the objects it stores. [Looking up the complement](./complement-lookup.md) rewrites a pair condition as a search for one exact value, stores what has been seen in a value-to-index map, and works through the check-before-insert order, duplicates, and the two-pass self-pair trap. [Counting the difference](./frequency-difference.md) replaces two counters and an equality check with one signed map, and covers the sign reading, the sum invariant, the copy-paste index trap, and the extra-character, ransom-note, and sliding-window variants. [Keeping only the best k](./bounded-heap.md) explains why a top-k heap is a min-heap, how the root becomes the eviction point, and where the direction, eviction order, and tiebreak go wrong.
