# Concepts

*The map from a question to the note that takes it up. Each definition carries its source; the Doc column points to the closest note, and the questions are the probes that keep the map honest.*

## Trade-offs

The consolidated trade-off matrix lives in [architecture/tradeoffs.md](architecture/tradeoffs.md). It uses one row per style or decision: **optimizes / costs / use when / avoid when / failure mode**.

Add new architecture choices there first. Individual notes may repeat a row for context, but the matrix is the source of truth. The anti-pattern [external calls inside a transaction](architecture/01e-external-calls-inside-transactions.md) is collected there too. The goal is not the matrix; it is [customer value](architecture/01f-customer-value-and-progress.md). For retryable operations, see [idempotency](architecture/01g-idempotency.md).

## Architecture

*The architecture notes as questions. Pick the question you cannot answer, follow the Doc link, and answer it in one sentence. If the answer is still "it depends," name the force and the revisit trigger.*

## Terminology traps

- **Temporal coupling is overloaded.** This series uses it for runtime ordering. Version-history analysis uses the same phrase for files that change together—logical or co-change coupling. They are different dependencies with different fixes.
- **Hidden coupling is not "any coupling you didn't notice."** A constructor parameter is visible coupling. Hidden coupling is a dependency that is absent from the static structure; the compiler cannot see it.
- **Semantic coupling is a form of hidden coupling.** The contract is the shared meaning of a value or field, not an import. Replacing `status = 2` with an enum makes the meaning visible; it does not remove the need for both sides to agree on it.
- **Logical / co-change coupling is evidence, not a runtime edge.** Files that change together may share a hidden concept or a copy-paste habit. It is a diagnostic signal, not the same thing as a call or a shared table.
- **Coupling to an abstraction is still coupling.** It reduces what the consumer must know. It does not remove the dependency, and an interface without a seam changes nothing.
- **An event bus removes the import edge, not the contract.** The topic string and payload shape are still shared knowledge; the fix is to make them explicit and versioned.
- **A shared database is a schema API.** Database-per-service moves the contract to an API; it does not make the services independent of each other.
- **A composition root is not a Service Locator.** A root may call `new` or `resolve`; application code may not. The distinction is who asks and where.
- **A DI container is not dependency injection.** DI is constructor or parameter injection; a container is optional automation used by the composition root.
- **Testing the root is not mocking the root.** A production-root smoke test runs the real graph; a test composition root runs fakes. They prove different things.
- **A module mock is not a contract test.** `jest.mock` replaces the concretion; it does not prove that the real adapter works.
- **Humble Object does not mean untested.** The root is too thin to unit-test line by line; the logic below is tested directly, and the root is tested by composition or integration tests.

### Architecture terminology traps

- **“No perfect architecture” is not relativism.** It does not mean all choices are equal; it means the choice must be defended against this problem’s forces.
- **“Best practice” is not a decision.** Best practice is context-free advice; architecture is a choice under constraints, with costs and a revisit trigger.
- **A module is not a layer.** Layers group code by technical role; modules group it by business capability and own data.
- **A modular monolith is not a layered monolith.** One deployable, explicit module boundaries, and schema per module are the point.
- **A C4 container is not a Docker container.** It is a deployable or runtime unit; one Docker container may host several C4 containers.
- **The outbox is not exactly-once.** It makes the business state and the event record atomic; consumers still see duplicates.
- **At-least-once is not a bug.** It is the practical delivery guarantee; duplicate processing is the bug.
- **Idempotency is not deduplication.** Deduplication is a mechanism; idempotency is the property you want.
- **Schema per module is not database per service.** One database can host separate schemas; extraction readiness is a benefit, not a guarantee.
- **A failure mode is not a cause.** “Relay lag” is a failure mode; “the relay was slow” is a cause. Blast radius is a separate dimension.
- **Service extraction is not a reward for clean code.** Extract for a concrete force; clean boundaries are a precondition.
- **Customer value is not a synonym for revenue.** It is the outcome the customer gets; revenue follows.
- **Working software is a leading indicator, not the goal.** It tells you the team can learn; customer value tells you whether it mattered.
